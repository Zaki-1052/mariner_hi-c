     Plan: Integrated Multi-Omic Genome Browser Locus Figures (Section 46)

     Context

     PI wants integrated genome browser-style figures (similar to TET paper
     Figure 6) that combine our multi-omic data at specific gene loci. The TET
     paper shows stacked tracks (5mC%, 5hmC%, RNA-seq, CTCF ChIP, CpG,
     conservation) at Bcl6/Foxo1 loci. Our project has significantly richer data
      -- 5mC/5hmC (8 samples each, BigWig), ChIP-seq (6 marks + DiffBind for 4),
      ATAC-seq, MeCP2, H2AK119ub, Hi-C loops (2,910 differential), and RNA-seq
     (DESeq2 results). No existing genome browser visualization code exists in
     the codebase. Starting with Syt1 (top coordinated gene: +18% mC, -15% hmC).

     Tool: Gviz (R/Bioconductor)

     Why Gviz over alternatives:
     - Already installed; R-native; integrates with existing pipeline sourcing
     _shared_config.R
     - DataTrack reads BigWig directly via rtracklayer
     - GeneRegionTrack from TxDb.Mmusculus.UCSC.mm10.knownGene for gene models
     - AnnotationTrack for BED peaks (ChIP, ATAC, K119ub, MeCP2, CpGs)
     - CustomTrack for Hi-C loop arcs (Bezier curves between anchors)
     - Outputs PDF/SVG/PNG compatible with Illustrator polish

     Not chosen: pyGenomeTracks (adds Python dependency), karyoploteR alone
     (more manual), IGV screenshots (not reproducible)

     Track Layout (Top to Bottom)

     Track 0:  Genome Axis (scale bar + chr coordinates)
     Track 1:  Gene Model (GeneRegionTrack from TxDb — exons, introns,
     direction)
               ─── RNA-seq annotation: log2FC & padj text on gene track ───

     ─── METHYLATION BLOCK (core dual-epigenetic story) ───
     Track 2:  5mC% Control (mean of 4 ctrl BigWigs, blue)
     Track 3:  5mC% Mutant (mean of 4 mut BigWigs, red)
     Track 4:  5mC Difference (Mut − Ctrl, bipolar red/blue)
     Track 5:  5hmC% Control (mean, blue)
     Track 6:  5hmC% Mutant (mean, red)
     Track 7:  5hmC Difference (Mut − Ctrl, bipolar)

     ─── CHROMATIN MECHANISM BLOCK ───
     Track 8:  H2AK119ub peaks (ctrl=gray, mut=purple — condition BEDs)
     Track 9:  H3K27me3 signal (BigWig, ctrl=blue overlay, mut=red overlay)
     Track 10: H3K27ac signal (BigWig, ctrl=blue, mut=red)
     Track 11: CTCF peaks (BED)

     ─── ACCESSIBILITY / READER BLOCK ───
     Track 12: ATAC-seq peaks (up=gold, down=green)
     Track 13: MeCP2 peaks (up=orange, down=purple)

     ─── ANNOTATION ───
     Track 14: CpG features (islands=dark, shores=medium, shelves=light)

     ─── 3D GENOME (gene-specific, omitted if no loops) ───
     Track 15: Hi-C loops (CustomTrack arcs, lost=red, gained=blue,
     width∝significance)

     Compact variant (for main figures): Tracks 0-4, 5 (ctrl only), 8, 11, 14,
     15 (~10 tracks)

     Averaging Strategy

     Average 4 ctrl and 4 mut samples → 2 condition tracks per mark. Import
     BigWig for target region only (memory-efficient), compute arithmetic mean
     signal per position. Follows preprocess_k119ub_bigwig.R pattern (lines
     130-157).

     Implementation Steps

     Step 1: Script skeleton

     - Create scripts/viz_sections/section_46_genome_browser_loci.R
     - Source _shared_config.R, define output dir 46_genome_browser

     - Configure ChIP BigWig paths (from peaks/bigwigs/macs2.narrow.aug18/)

     Step 2: Helper — get_gene_region(gene_symbol, extend_bp)

     - TxDb + org.Mm.eg.db symbol → GRanges (same logic as section_27 GREAT
     domains)
     - Return gene body ± extend_bp (default 50kb)

     Step 3: Helper — average_bigwigs_in_region(bw_paths, region_gr)

     - rtracklayer::import.bw(path, which = region_gr) for each sample
     - Compute per-position mean across samples using coverage/Views pattern
     - Return GRanges with score = mean_signal

     Step 4: Helper — compute_difference_signal(ctrl_gr, mut_gr)

     - Align coordinates, compute mut_score - ctrl_score
     - Return GRanges for difference DataTrack

     Step 5: Build Gviz tracks for Syt1 proof-of-concept

     - GenomeAxisTrack, GeneRegionTrack, DataTracks (mC, hmC), AnnotationTracks
     (peaks, CpGs)
     - Test with plotTracks(), tune sizes parameter for relative heights

     Step 6: Hi-C arc CustomTrack

     - Filter extended_characterized_loops.tsv for loops with anchor in view

     - Draw Bezier arcs in CustomTrack plotting function
     - Color by direction (lost=red, gained=blue), line width ∝ -log10(FDR)

⏺ The issue is in load_peak_as_granges(). The function reads BED files with
  header = FALSE, then does:

  gr <- GRanges(seqnames = df$V1, ranges = IRanges(start = df$V2, end = df$V3))

  Some of the BED files (like the CpG annotations) have a header row
  (Chromosome\tStart\tEnd\tAnnotation). When read with header = FALSE, that
  header becomes a data row where V1 = "Chromosome", V2 = "Start", V3 = "End".
  When R tries to coerce "Start" to numeric for IRanges, it produces NA. The
  GRanges() constructor then gets NA in seqnames or ranges and throws 'seqnames'
   cannot contain NAs.

  The fix I was about to apply (that you rejected because I was also adding a
  tryCatch fallback) was to filter out rows where V2/V3 aren't numeric before
  constructing the GRanges:

  valid <- !is.na(df$V1) & !is.na(suppressWarnings(as.numeric(df$V2)))
  df <- df[valid, , drop = FALSE]
  df$V2 <- as.numeric(df$V2)
  df$V3 <- as.numeric(df$V3)
  stopifnot(nrow(df) > 0)

  This drops header-like rows where the coordinate columns contain text, then
  fails hard (stopifnot) if nothing remains. No fallback, no degradation — just
  proper input validation at the system boundary.

  The separate load_cpg_annotation() function doesn't have this problem because
  it reads with header = TRUE, which correctly skips the header row.
